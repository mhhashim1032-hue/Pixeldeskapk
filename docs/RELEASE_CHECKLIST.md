# PIXEL DESK release-candidate checklist

## Current artifact status

CI produces an **installable, debug-signed ARM64 APK candidate**. It is not a production release: the Android debug signing key is generated by the CI runner, the app has not passed physical-device integration testing, and no production signing key or release policy has been configured.

The workflow verifies the APK signature with Android `apksigner`, checks that `lib/arm64-v8a/libpixeldeskpty.so` is packaged, calculates SHA-256, and uploads the APK with a build manifest.

## Download the CI APK

1. Open the repository's **Actions** tab.
2. Open the latest successful **Android CI** run for the branch/commit you want to test.
3. Download the artifact named `pixeldesk-installable-debug-candidate`.
4. Extract the ZIP. It contains:
   - `app-debug.apk`
   - `app-debug.apk.sha256`
   - `manifest.txt`
5. Compare the APK's SHA-256 against the value in `manifest.txt` before installing.

## Install on the Pixel

1. Transfer `app-debug.apk` to the Pixel 9 Pro XL.
2. Open it from Files and approve Android's one-time **Install unknown apps** permission for the app used to open it, if Android requests it.
3. Install the APK.
4. Open PIXEL DESK and check Settings/runtime diagnostics.
5. Create a disposable Debian environment and validate rootfs download, extraction, first shell command, DNS, APT and terminal input/output.
6. Test start, stop, restart, backup/export and cancellation. Keep personal files out of test environments.

A CI artifact from a different run may have a different debug signing certificate. Android may refuse an in-place update over an APK signed with another key; uninstalling the previous debug build may be required and can erase its app-private data. Back up any environment before replacing the app.

## Required before a public production release

- Complete physical Pixel 9 Pro XL testing of PRoot, PTY, DNS, APT, rootfs extraction and backup/export.
- Resolve all dependency and bundled PRoot licensing obligations and publish required corresponding source.
- Complete privacy, data safety, permission and store-policy review.
- Configure a dedicated production keystore in protected CI secrets; never commit a keystore or passwords.
- Add a release signing configuration and verify the signed APK/AAB using `apksigner` / bundle tooling.
- Test upgrade behavior, signature continuity, rollback and backup restoration.
- Run release build, tests, lint and artifact verification from a tagged commit.
- Publish release notes with tested Android versions, device coverage, known limitations and SHA-256.

## Signing and artifact integrity

The CI debug artifact is signed only to make it installable for development testing. It is not suitable for Play Store publication or a trusted public distribution channel. Never treat a debug certificate as the product's permanent signing identity.

The manifest records the application ID, version code/name, minimum Android API, included native ABI, Git commit, build timestamp, APK byte size and SHA-256 digest. The digest detects accidental corruption; it does not prove who built the APK. Verify the GitHub Actions run and source commit as well.

## Release blockers

- Physical device validation remains incomplete.
- Linux GUI, Windows EXE compatibility and VM support are not available features.
- No production signing key is configured.
- No repository-wide project license has been selected.
